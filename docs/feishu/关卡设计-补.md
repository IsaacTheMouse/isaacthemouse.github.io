设计过程很高程度地参考了 [BV1Qe411U7XD](https://www.bilibili.com/video/BV1Qe411U7XD/)，感谢 SteveLee 的这个思路分享，让我从一开始就能以一个清晰的逻辑进行关卡设计。

:::

在本项目中，难度最高的两个关卡实际上是在项目的最前期被设计出来的。此时我还处于机制设计的摇摆阶段，虽然已经有了四个可用的机制，但我无法确定机制之间的交互是否是有机的，能否创造足够的深度。因此，我急需设计一个有趣的关卡作为证明。

接下来我分步详细描述我是如何完成一个复杂关卡的设计的： 

1. 确定关卡职责（目标）  
在这里我想要达成的是，我想要设计一两个稍微复杂些，逻辑步骤足够多的关卡，同时它需要有一个足够精妙的核心谜题。一方面是为了让我能够对机制之间的联系和能达成的深度有一个直观的概念，另一方面这种围绕核心谜题的设计也更容易让玩家感受到尤里卡。  
在其他关卡中，这个职责还可能是提供引导、引入/强化机制，或是几者的组合。
2. 统筹要使用的元素（机制）  
说实话，作为一个可用机制很少的项目，我其实并没有什么选择的余地，并且为了尽可能探索深度，我只是把所有能用的机制全部罗列出来。
3. 问题  
到这一步一些问题开始浮现出来：为什么这些机制是有趣的？通过玩弄不同机制，我可以做到哪些很酷的事情？如果只考虑其中的某两个机制组合呢？我该如何设计关卡中的核心谜题，使其能够支撑足够多的逻辑步骤？  
在探索这些问题的过程中，我逐渐发现了一些有意思的点子，例如：  
a. 对一个"锁"，如果将其横向拉长放置，则玩家可以在关卡的部分过程中将其视为“桥梁”来使用，而玩家在拿着钥匙将其打开后，则无法再继续这么做。这天然地为关卡引入了一定的逻辑先后顺序，玩家需要思考哪些行为是需要在锁被打开之前完成的，而哪些需要打开之后再做。  
于是我把这些点子记录下来，并进入到下一个阶段。
4. 点子  
通过组合我获得的点子，我发现如果将前文提到的“通过踩在锁上来通过横向长距离”与“箱子可以提供落脚点”结合会很有趣，可以构造一个“通过踩在箱子上达到拿着钥匙跳过锁而不触发它”的结构（见下图）。于是我就以此为核心开始起草关卡。  
类似的，我还发现了一个其他的点子也足已支撑一个关卡的体量，但此处我们先专注于上面我提到的这个点子。

![设计草稿中这一点子的雏形](b28e901f29e4210ef31ddee2567bcba1.png)

5. 完善  
定下了关卡的核心体验后，我需要做的就是完善这个关卡，使其能通过严谨的逻辑进行推导，且相对有趣。  
比起 SteveLee 原视频中使用的纯文字设计，我还是更喜欢使用绘图的方式来整理思路，我认为这会更直观。（或许因为我是在2D项目中工作而他是3D？）  
我先是在草稿中设计了最简单的能达成核心体验的关卡蓝图（见图左上），随后通过反向的逻辑推导和多次的纸上模拟，基本确定了一个至少拥有8个步骤的关卡。

### 关卡与机制的交叉验证
我在关卡设计和机制筛选中有过一段时间的反复，首先我根据脑暴的结果进行关卡的尝试，构思出了两个较为复杂的关卡，通过这种方式验证了机制的可玩性。

举一个细节上的例子，一开始我不确定箱子的设计应该做成什么样，因为二者各有各的优点，无法直接判断出某个设计一眼比另一个好。这时就需要把设计扔进关卡里去看待，如果一个关卡用A设计，玩家玩起来的感觉如何？用B设计呢？是否存在某个复杂的关卡只能通过A设计达到？

我的做法是先根据不同设计进行一定范围的尝试，做出不完整的关卡片段。这种片段包含一个关卡的核心体验，可以通过后续的简单劳动扩充成完整的关卡。然后在这个地方我发现设计A有很清晰的设计思路，并且后续拓展性也很强，至少在 GameJam 的尺度下完全够用，因此我就舍弃了设计B。

在这个地方还有一个细节就是，当你发现一个设计足够达成自己的目标时，适当舍弃其他可能性是可以被接受的，GJ 时间上比较紧张，不可能做到尽善尽美。在我的例子中，两个设计相互之间第一眼无法决出高低本身就意味着差距没有大到一个程度，跳过一个选项在压力较大的情况下是比较明智的选择。

### 拒绝“教玩家玩游戏”
写不动啦！

前提：明确目标群体

确保玩家能一直有方向（一眼看到终点）的前提下尽量做到每一步之间逻辑严谨

可选的引导→让玩家感到被尊重 / 区分信息层次

非设计师测试的重要性：知识诅咒 / 片叶障目

“可控的选择”→魔术中的“强选”→在剧情向游戏中的应用
